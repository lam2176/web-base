## 📊 Database Schema Overview

**Key entities and relationships:**
1. **products**
   - id, slug, name_vi, name_en, description_vi, description_en
   - original_price, sale_price, discount_percentage
   - stock_quantity, is_out_of_stock
   - category_id (FK), featured, status
   - meta_title, meta_description
   - created_at, updated_at

2. **product_variants**
   - id, product_id (FK), name, value (e.g., "Color: Red")
   - price_adjustment, stock_quantity

3. **product_images**
   - id, product_id (FK), media_id (FK), order, is_primary

4. **categories**
   - id, slug, name_vi, name_en, description_vi, description_en
   - parent_id (FK - self reference for hierarchy)
   - order, status

5. **media**
   - id, filename, filepath, mimetype, size
   - created_at

6. **pages**
   - id, slug, title_vi, title_en, content_vi, content_en
   - meta_title, meta_description, status

7. **store_info**
   - id, name_vi, name_en, logo_id (FK to media)
   - address, hotline, email, description_vi, description_en
   - currency, shipping_fee, bank_info
   - social_links (JSON)

8. **banners**
   - id, title_vi, title_en, subtitle_vi, subtitle_en
   - image_id (FK to media), link, order, status

9. **coupons** (event-based discounts)
   - id, code, name_vi, name_en
   - discount_type (percentage/fixed), discount_value
   - start_date, end_date, status
   - apply_to (all/category), category_ids (JSON array)

10. **discount_codes** (customer input codes)
    - id, code, name
    - discount_type (percentage/fixed), discount_value
    - max_usage, current_usage, expiry_date, status

11. **users**
    - id, email, password (hashed), role (admin/staff)
    - refresh_token, created_at

12. **orders**
    - id, order_number, customer_name, customer_email, customer_phone
    - customer_address, subtotal, shipping_fee, discount_amount
    - total, status (pending/confirmed/shipping/completed/cancelled)
    - discount_code_id (FK), notes, created_at

13. **order_items**
    - id, order_id (FK), product_id (FK)
    - product_name, variant_name, quantity, price, total

14. **translations** (for dynamic content)
    - id, entity_type, entity_id, field, locale, value

## 🔐 Authentication Flow
1. Admin login → POST `/api/auth/login` → returns `access_token` + `refresh_token`
2. Store tokens in httpOnly cookies or localStorage
3. Include `Authorization: Bearer <access_token>` in API requests
4. Refresh token → POST `/api/auth/refresh` when access token expires
5. Protected routes use JWT Guard in backend
6. Frontend redirects to login if unauthorized

---

## 🛒 Shopping Flow
1. Browse products → Filter by category, search, price range
2. View product detail → Select variant → Add to cart (stored in Zustand)
3. View cart → Update quantities → Apply discount code (optional)
4. Checkout → Fill customer info → Review order (subtotal + shipping + discount)
5. Submit order → Backend creates order → Returns order confirmation + bank info
6. Show success page with bank transfer details

---

## 🎟️ Discount Logic
- **Coupons**: Auto-apply if active (check start_date/end_date)
  - Apply to all products or specific categories
  - Calculate discount in cart/checkout
- **Discount Codes**: User manually enters code
  - Validate: code exists, not expired, usage count < max_usage
  - Apply discount if valid
  - Increment usage count on order creation
- Priority: Discount code overrides coupon if both applicable

## 🌐 i18n Implementation
- Backend: Store translations in database (`translations` table) or JSON fields per entity
- Frontend: Use `next-intl` with `/[locale]/` routing
- Language switcher component changes locale → re-fetches translated content
- API returns content based on `Accept-Language` header or `locale` query param
